DEFINITION

AIOS 不是一个工具，而是组织的操作系统

NOT

不只是

✕
一个简单的 AI Agent 集合
✕
一个任务管理工具
✕
一个自动化工作流平台
BUT

而是

✓
可标准化定义、被软件承载、被不同业务复制的组织形态
✓
由 Human 与 AI Agent 共同运行、通过实践不断优化自身规则的智能组织
✓
一套能够不断复制项目、组织和组织能力的生产体系

本仓库的 dsh-superagent 是这套操作系统的第一个可运行原型：已跑通一个组织实例的闭环；内核、模板与复制的自动化仍是方向（本 deck 末尾标注现状）。

WHY · 组织为什么需要操作系统

复制的是组织能力，不是重新组班子

传统做法的问题AIOS 的主张
每遇到新机会就重新组班子、重新设计管理方式先有组织内核，再用模板实例化，复制组织能力
流程靠人记、靠口口相传，成员一走就断档规则进宪章（版本化），知识进公共资产库，不依赖个人记忆
AI 只是帮人干更多活的工具AI 与 Human 是同一组织里的成员与 Worker，同一治理框架下协作
SOP 是写死的一成不变文档SOP 在执行与复盘中持续改进，经评审与版本管理
职责模糊、交付无验收标准每个任务有负责人、输入、验收标准与唯一权威载体

一句话：不建一个项目，而建一套能不断复制项目、组织和组织能力的生产体系。

DESIGN PRINCIPLES

六条设计原则

01

规则驱动

先有宪章才有工作；没有宪章、职责未定义、岗位不承接、派给 PM，都在主机侧被拒绝。

02

单一事实来源

任务只来自 Kanban；宪章/职责在 Gitea；交付物唯一权威载体；状态与结果回写看板。

03

分层继承

内核 → 模板 → VSM 实例 → 独立运行与反向贡献。

04

岗位与职责分离

岗位长期存在、持有身份；职责一次性授权、随交付结束，不持有外部身份。

05

人类保留最终权力

AI 在授权内自主执行；宪章发布、权限边界与异常升级由人掌握。

06

可复制

成熟规则沉入内核被所有实例继承；业务特有经验留在各自 Workspace。

CONCEPTS · 组织与人

叙事术语 ↔ 系统实现

叙事概念系统映射状态
Organization 组织一个 Kanban 项目 + 项目档案（岗位/宪章镜像/职责说明/看板订阅）✅
PM 领导者PM 岗位（主 Session / Team 视角）：宪章、派工、异常、审进度✅
Member 成员AI 成员 = 岗位（Post）；Human 通过来源消息、看板指派与审批参与🚧 无统一成员目录
Role / 岗位岗位的 role（pm/worker）+ 身份绑定 + 监听列 + WIP✅

身份取舍：岗位在 Kanban 用登录邮箱（宿主映射成使用者 id），Gitea/ntfy 各自有身份；跨来源“同一个人”只作提示词上下文与档案信息（见 docs/001）。

CONCEPTS · 工作与治理

Task → Duty → Ticket → Deliverable

叙事概念系统映射状态
Worker 执行者Worker 岗位的执行器 Session：每个工单一个执行会话与工作目录✅
Charter 宪章项目宪章：Gitea 宪章仓库 README.md（或 Kanban 描述镜像）；版本化、每周≤1 版✅
Responsibilities 职责说明宪章同目录 duties.md：目标/完成/载体/知识/资源/工具/技能/接单/步骤/常见坑/承接岗位✅
Task 任务Kanban 卡片：duty:/kind:/repo: 标签 + assignee；唯一任务来源✅
Pipeline 流程看板列（价值流）+ 宪章流程语义 + 职责步骤；复杂分支仍靠文档表达🚧 无流程引擎
Duty / 工单Ticket：接受时创建，携带 Mandate、Duty brief、宪章版本；随交付结束✅
Deliverable 产出代码 = Gitea PR；文档/方案 = MinIO 对象；看板只留进度与结果✅
Knowledge / Review / EvolutionMinIO + 仓库文档/技能 + 宪章职责版本历史；周复盘制度🚧 无统一索引/自动复盘
INFRASTRUCTURE · 四个系统，各司其职

不让信息四处分散

组织基础设施系统映射组织职责明确不承担
组织工作空间Kaneo Workspace / Project组织、项目、任务、看板状态、日志与回写不存代码、不存文档产物
组织宪章Gitea 宪章仓库规则、SOP、岗位职责说明；发布 = 提交，历史 = 版本不产生任务（不监听 Issue/PR）
组织资产库MinIO / S3交付物、方案、memo、共享资产不参与调度与授权
组织通信渠道ntfy事件、通知、异常提醒；带 tag 的消息可先入库成卡不构成授权（公开 topic 仅上下文）
组织运行环境DSH Host（SuperAgent bundle）运行主 Session 与执行器 Session，执行闸门、派工、回写、交付不替人做规则决策；不直接改看板

统一身份与关联：Kanban 登录邮箱 → 使用者 id；Gitea 账号；ntfy sender。跨系统「同一个人」只作上下文，系统不建跨来源账号映射。

INITIALIZATION · 从默认规则到正式运行

PM 负责完成首次初始化

01 — 05
✓创建组织工作空间（Kanban Workspace/Project）
✓初始化宪章仓库（Gitea）
✓确认目标与客户价值（宪章 Objectives）
✓登记岗位（AI 成员）与 Human 参与方式
✓明确岗位职责（duties.md + 承接岗位）
06 — 10
✓建立 Team 与协作关系（当前以项目/看板协同代替）
✓初始化项目流程与任务流程（看板列 + 宪章语义）
✓配置公共资产空间（MinIO 桶与凭据）
✓创建通知频道（ntfy topic 与入库 tag）
✓确认权限、授权与审计（canManageFlow / 决策记录）

默认配置可以有，模糊责任不可以有：每个岗位有明确身份与职责，每个任务有负责人、输入与验收标准，每个交付物有唯一权威载体。

OPERATING LOOP · 从卡到交付

一张卡如何变成可验收的交付

Kanban 卡片唯一任务来源
→
指派给岗位assignee = 岗位账号
→
接单读回 + 租约
→
工单 + Duty钉住宪章版本
→
执行器交付PR / MinIO 对象
→
宿主回写状态 + 日志 + 引用

Kanban 唯一任务源

评论 @ 岗位不算派工；只有看板上的卡才是任务。

唯一权威载体

代码走 PR，文档/方案存 MinIO；看板只留进度与结果。

单写者纪律

看板由宿主写；Worker 报告状态，不自己搬卡。

GOVERNANCE · 不可谈判的规则

规则不是建议，是主机侧闸门

规则行为落点
没有宪章不可开工宪章版本 0 → noCharter 忽略，不建工单charter.ts
职责必须先定义duty 未定义 → dutyUndefined；岗位不承接 → dutyUnsupportedduties.ts
PM 不给自己派活卡片落在 PM 岗位 → pmExecutionNotAllowed；宪章写明「PM 可执行职责」才放行pm-execution.ts
任务只来自看板Gitea 只做宪章仓库；ntfy 带 tag 的消息先入库成卡sources/gitea.ts · ntfy.ts
权限先验证切 Team 视角前查 canManageFlow；岗位视角来源只读capabilities.ts · 面板
宪章版本纪律每周最多发布一版（覆盖需说明理由），历史保留，工单钉住开工版本charter.ts · narrative.ts
复用公共资产文档/方案存 MinIO 不贴评论；代码走 PR；知识进仓库文档prompts/work.md
DELIVERY · 产出有唯一权威载体

一处载体，处处可引用

产出类型权威载体回写看板
代码变更Gitea PR（一仓一目录一 PR）PR 链接 + 评审状态
文档 / 方案MinIO 对象（来源卡可覆盖端点/桶/凭据）对象键 + URL
memo / 决策MinIO 对象（长）或任务评论（短）摘要 + 结论
工作日志Kanban 任务评论（追加式）即为看板内容

交付前自查

✓只改了被授权的仓库与目录
✓产出有可点击引用
✓工作日志已追加、状态已更新

边界

不跨工作目录交付；需求有歧义不要猜：提问并转 blocked，进 PM 的异常队列。

看板由宿主写：岗位只报告，不自己搬卡。

KNOWLEDGE · 组织学习

沉淀可复用的能力，不只保存交付物

沉淀类型载体状态
交付物（方案/文档/报告）MinIO 对象（固定 key，可回读）✅
SOP 与操作指南SOP.md / SOP.html / STORY.md✅
方法论与决策记录RD.md / docs/ / TDD/ / HANDOFF.md✅
规则与职责宪章 README.md / duties.md（commit 历史 = 版本）✅
工具与技能仓库内 Agent Skill、提示词、bundle 代码✅
失败案例与改进TDD 记录、HANDOFF 修正、story 回归🚧 未自动提炼模板

知识不能随 Member 离开而消失：规则进宪章、经验进仓库、交付物进对象存储，而不是留在某次对话或某个人脑子里。

REVIEW & EVOLUTION

复盘不是汇报，是检查组织自身

每周复盘问什么

✓客户价值是否真正实现？
✓目标与 Task/Pipeline 是否有效？
✓Team 协作与岗位职责是否合理？
✓SOP 是否有重复、低效或错误？
✓知识资产是否有效沉淀？
✓哪些工作可自动化、哪些规则要改？

三层进化

1
执行进化：Worker 在任务内优化方法与质量
2
团队进化：改 duties/流程/岗位与能力配置
3
组织进化：改宪章/结构/权限/方法论（≤每周一版）

复盘结果必须有行动：一般改进进 Kanban 成新卡；知识进 Gitea/MinIO；规则修改发新宪章版本，并经过评审与版本管理。
