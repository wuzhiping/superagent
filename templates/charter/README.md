# 宪章 · <项目名>

> 这是 **Quick Small Start** 的宪章模板：填 3 处（项目名、流程列、岗位与职责）即可开始跑第一张卡；其余按需再长。
> 合并方式与 30 分钟清单见产品仓库 `CHARTER-QUICKSTART.md`。

## 目标
- 这一期为客户/团队创造什么：<一句话>
- 本期不做什么：<一句话>

## 当期流程（看板列）
- `to-do → in-progress → in-review → done`
- 监听列：`to-do`；认领列：`in-progress`；交付列：`done`
- 卡进监听列之前挂好标签：`duty:` / `kind:` / `repo:`

## 岗位职责
- **PM**：派工、处理异常、验收；负责复盘与能力资产；不直接产出交付物。
- **Worker**：开工先读本期宪章（报版本）→ 读卡 → 交付 → 报告；不代领、不自领没有指派给自己的卡。
- 具体职责见 `duties/`（一职责一文件；岗位卡里选中它才算承接）。

## 交付标准
- **非代码**：放 MinIO（桶 `<bucket>`），key 固定 `deliverables/<projectId>/<ticketId>/<file>`；评论只写 `bucket/key` 与结论。
- **代码**：走 Gitea PR，描述写清改动与验证证据；卡上 `repo:owner/name` 声明动哪个仓库。
- **没有载体不算完成**；草稿只能报告 `blocked`，不能报 `ready`。

## 沟通
- 项目主题：`pub_<projectId>`（如用 ntfy）；有阻塞写在卡片评论或 topic。
- 人反馈走卡片/线程；执行器只报告，宿主写评论与移列。

## 复盘与改版
- 每周一次 30 分钟复盘：写 `reviews/weekly/YYYY-Www.md`，更新 `context/retrospectives.md`。
- 宪章最多每周一版；改版走 PR（变更理由/影响/验收/回滚），发布后在面板同步。

## 能力供给（Quick Small Start 的最小版）
规则之外，还要供给能力资产；先跑两条，其余按需启用：

| 层 | 目录 | 先用来做什么 |
| --- | --- | --- |
| 职责 | `duties/` | 每个岗位至少 1 条可派工的职责 |
| 复盘 | `reviews/` | 周复盘（日/月模板已在，可后启用） |
| 上下文 | `context/` | 最新复盘总结 + 1 个领域对象 |
| 知识 | `KE/` | 每周至少 1 条过 MAKE 的知识 |
| 技能 | `skills/` | 有真实使用的技能再发布（不要空建） |

- 检查清单与成长路线见产品仓库 `CAPABILITY.md` / `EA.md`。
- 铁律：没有 Owner 的资产不算落地；没人用的资产定期清理。
