# 职责（duties）

一职责一文件：`duties/<id>.md`，文件名就是职责 id（小写字母、数字、短横线）。
以 `_` 开头的文件（如 `_TEMPLATE-*.md`）**不会**被系统当成职责，可以安全保留作模板。

## 快速创建一个职责（2 分钟）

1. 复制一个模板：`_TEMPLATE-code.md`（代码交付）、`_TEMPLATE-doc.md`（文档交付）或 `_TEMPLATE-pm.md`（PM 运营）。
2. 改名成你的 id，例如 `duties/api.md`。
3. 填 `承接岗位`（必须与项目里登记的岗位 id 一致）、目标、完成、载体、步骤。
4. 在面板「项目与岗位 → 职责说明」里发布，并在岗位卡「接哪些职责」下拉里选中它。
5. 卡片打标签 `duty:<id>` 并指派该岗位，才会进入这张职责。

## 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 承接岗位 | 是 | 哪个岗位能接（多个用顿号分隔） |
| 目标 | 是 | 这类活干什么、为谁 |
| 完成 | 是 | 可验收的完成定义（载体在哪、评论写什么） |
| 载体 | 是 | `code`（Gitea PR）/ `doc`（MinIO）/ `comment`（卡片评论） |
| 宪章关注 | 否 | 开工前要重点看的宪章条款 |
| 知识 / 资源 / 工具 / 技能 | 否 | 干活需要的东西 |
| 接单 | 是 | 什么条件下领、什么条件下退回 |
| 步骤 | 是 | 3–8 步，能照着做 |
| 常见坑 | 否 | 真实踩过的坑，越具体越好 |

## 与复盘/知识的关系

职责里反复出现的动作 → 提取为 `skills/`；职责里反复出现的判断 → 写进 `KE/`；规则性约束 → 写回宪章。
